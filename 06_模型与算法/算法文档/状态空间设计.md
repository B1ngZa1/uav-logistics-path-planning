# 无人机物流配送项目 - 11维连续状态空间设计文档

## 一、概述

### 1.1 设计目标

本文档定义无人机物流配送系统的11维连续状态空间，用于深度强化学习（PPO）算法的训练与执行。状态空间的设计需满足以下要求：

1. **完备性**：包含决策所需的全部环境信息
2. **紧凑性**：避免冗余维度，降低计算复杂度
3. **可编码性**：支持连续状态归一化与离散状态独热编码
4. **可扩展性**：便于后续引入新的状态要素

### 1.2 状态空间总览

状态向量 s ∈ R^11 由以下11个维度组成：

s = [x, y, z, vx, vy, vz, d_goal, d_obs, d_uav, E_remain, p_delivery]^T

---

## 二、状态要素定义

### 2.1 三维位置 (x, y, z)

**物理含义**：无人机在三维空域中的当前位置坐标

**数学定义**：
p = (x, y, z) ∈ [0, 100] × [0, 100] × [10, 50] (米)

**取值范围**：

| 维度 | 符号 | 最小值 | 最大值 | 单位 | 说明 |
|------|------|--------|--------|------|------|
| X坐标 | x | 0 | 100 | 米 | 东西方向 |
| Y坐标 | y | 0 | 100 | 米 | 南北方向 |
| Z坐标 | z | 10 | 50 | 米 | 垂直高度，最低10米避障 |

**约束条件**：
- 0 ≤ x ≤ 100
- 0 ≤ y ≤ 100
- 10 ≤ z ≤ 50

### 2.2 三维速度 (vx, vy, vz)

**物理含义**：无人机在三个轴向的速度分量

**数学定义**：
v = (vx, vy, vz) ∈ [-15, 15]^3 (m/s)

**取值范围**：

| 维度 | 符号 | 最小值 | 最大值 | 单位 | 说明 |
|------|------|--------|--------|------|------|
| X方向速度 | vx | -15 | 15 | m/s | 东西方向速度 |
| Y方向速度 | vy | -15 | 15 | m/s | 南北方向速度 |
| Z方向速度 | vz | -15 | 15 | m/s | 垂直方向速度 |

**约束条件**：
||v|| = sqrt(vx^2 + vy^2 + vz^2) ≤ v_max = 15 m/s

### 2.3 目标距离 d_goal

**物理含义**：当前位置到目标配送点的欧氏距离

**数学定义**：
d_goal = ||p - p_goal||_2 = sqrt((x - xg)^2 + (y - yg)^2 + (z - zg)^2)

其中 p_goal = (xg, yg, zg) 为目标点坐标。

### 2.4 障碍物距离 d_obs

**物理含义**：当前位置到最近障碍物表面的欧氏距离

**数学定义**：
d_obs = min_{o∈O} ||p - o||_2

其中 O = {o1, o2, ..., oK} 为障碍物集合。

**安全阈值**：d_safe,obs = 5 米

### 2.5 无人机距离 d_uav

**物理含义**：当前位置到最近其他无人机的欧氏距离

**数学定义**：
d_uav = min_{j≠i} ||p_i - p_j||_2

**安全阈值**：d_safe,uav = 10 米

### 2.6 剩余电量 E_remain

**物理含义**：电池剩余电量百分比

**数学定义**：
E_remain = E_current / E_battery ∈ [0, 1]

其中 E_battery = 500 Wh 为电池总容量。

**电量状态划分**：
- 电量充足：E_remain > 0.5
- 电量中等：0.2 < E_remain ≤ 0.5
- 电量不足：E_remain ≤ 0.2

### 2.7 配送进度 p_delivery

**物理含义**：已完成配送任务的数量

**数学定义**：
p_delivery ∈ {0, 1, 2, ..., M}

其中 M 为总配送订单数。

**场景配置**：
- 基础场景：M=5
- 中等场景：M=10
- 复杂场景：M=20

## 三、状态编码方式

### 3.1 编码策略总览

| 状态类型 | 包含维度 | 编码方式 | 输出维度 |
|----------|----------|----------|----------|
| 连续状态 | x, y, z, vx, vy, vz, d_goal, d_obs, d_uav, E_remain | 归一化 | 10 |
| 离散状态 | p_delivery | 独热编码 | M+1 |

**最终编码维度**：D_encoded = 10 + (M + 1)

### 3.2 连续状态归一化

采用Min-Max归一化，将连续状态映射到 [0, 1] 区间：

hat_s_i = (s_i - s_min) / (s_max - s_min)

**归一化参数表**：

| 维度 | 符号 | s_min | s_max | 归一化公式 |
|------|------|-------|-------|-----------|
| X坐标 | x | 0 | 100 | hat_x = x / 100 |
| Y坐标 | y | 0 | 100 | hat_y = y / 100 |
| Z坐标 | z | 10 | 50 | hat_z = (z - 10) / 40 |
| X速度 | vx | -15 | 15 | hat_vx = (vx + 15) / 30 |
| Y速度 | vy | -15 | 15 | hat_vy = (vy + 15) / 30 |
| Z速度 | vz | -15 | 15 | hat_vz = (vz + 15) / 30 |
| 目标距离 | d_goal | 0 | 180 | hat_d_goal = d_goal / 180 |
| 障碍物距离 | d_obs | 0 | 180 | hat_d_obs = d_obs / 180 |
| 无人机距离 | d_uav | 0 | 180 | hat_d_uav = d_uav / 180 |
| 剩余电量 | E_remain | 0 | 1 | hat_E_remain = E_remain |

### 3.3 离散状态独热编码

配送进度 p_delivery 采用独热编码：

o_delivery = OneHot(p_delivery) ∈ {0, 1}^(M+1)

## 四、Python实现

```python
import numpy as np

class StateEncoder:
    def __init__(self, max_orders=20):
        self.max_orders = max_orders
        self.continuous_dim = 10
        self.discrete_dim = max_orders + 1
        self.encoded_dim = self.continuous_dim + self.discrete_dim

        # 归一化参数
        self.s_min = np.array([0, 0, 10, -15, -15, -15, 0, 0, 0, 0])
        self.s_max = np.array([100, 100, 50, 15, 15, 15, 180, 180, 180, 1])

    def encode(self, state):
        """编码单个状态"""
        continuous_state = state[:10]
        discrete_state = int(state[10])

        normalized_continuous = (continuous_state - self.s_min) / (self.s_max - self.s_min)

        one_hot_discrete = np.zeros(self.discrete_dim)
        one_hot_discrete[discrete_state] = 1.0

        encoded_state = np.concatenate([normalized_continuous, one_hot_discrete])
        return encoded_state
```

## 六、总结

### 6.1 设计要点

1. **11维状态空间**：包含位置、速度、距离、电量、任务进度五类信息
2. **混合编码方式**：连续状态归一化 + 离散状态独热编码
3. **理论无限空间**：连续状态空间包含无限多个状态点
4. **实际有限采样**：每次训练采样256个状态，依赖深度学习泛化能力
5. **模块化设计**：状态编码器独立封装，便于测试与复用

### 6.2 设计优势

1. **信息完备**：涵盖决策所需的全部环境信息
2. **编码高效**：归一化+独热编码，便于神经网络处理
3. **维度适中**：11维原始状态，编码后16-31维，计算复杂度可控
4. **可扩展性**：支持不同订单数量的场景配置
