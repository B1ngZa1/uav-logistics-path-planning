## 一、问题定义与数学建模

### 1.1 符号定义

| 符号 | 类型 | 说明 |
|------|------|------|
| $\mathcal{O} = \{o_1, o_2, \ldots, o_M\}$ | 集合 | 配送订单集合，共 $M$ 个订单 |
| $\mathcal{U} = \{u_1, u_2, \ldots, u_N\}$ | 集合 | 无人机集合，共 $N$ 架无人机 |
| $\mathbf{A} \in \{0, 1\}^{N \times M}$ | 矩阵 | 分配矩阵，$A_{ij} = 1$ 表示订单 $o_j$ 分配给无人机 $u_i$ |
| $\mathbf{p}_i = (x_i, y_i, z_i)$ | 向量 | 无人机 $u_i$ 的当前位置 |
| $\mathbf{d}_j = (x_j^d, y_j^d, z_j^d)$ | 向量 | 订单 $o_j$ 的配送目标位置 |
| $\mathbf{s}_j = (x_j^s, y_j^s, z_j^s)$ | 向量 | 订单 $o_j$ 的取货位置 |
| $t_j^{\text{deadline}}$ | 标量 | 订单 $o_j$ 的配送截止时间 |
| $t_j^{\text{create}}$ | 标量 | 订单 $o_j$ 的创建时间 |
| $w_j$ | 标量 | 订单 $o_j$ 的货物重量（kg） |
| $E_i^{\text{remain}}$ | 标量 | 无人机 $u_i$ 的剩余电量（Wh） |
| $Q_i^{\text{max}}$ | 标量 | 无人机 $u_i$ 的最大载重量（kg） |
| $E_i^{\text{max}}$ | 标量 | 无人机 $u_i$ 的电池容量（Wh） |

### 1.2 订单模型

每个订单 $o_j$ 定义为一个七元组：

$$
o_j = (\mathbf{s}_j, \mathbf{d}_j, w_j, t_j^{\text{create}}, t_j^{\text{deadline}}, \text{priority}_j, \text{status}_j)
$$

其中：
- $\mathbf{s}_j$：取货位置（仓库/商家位置）
- $\mathbf{d}_j$：配送目标位置（客户位置）
- $w_j$：货物重量
- $t_j^{\text{create}}$：订单创建时间
- $t_j^{\text{deadline}}$：配送截止时间
- $\text{priority}_j \in \{1, 2, 3, 4, 5\}$：优先级（5为最高）
- $\text{status}_j \in \{\text{pending}, \text{assigned}, \text{picking}, \text{delivering}, \text{completed}, \text{overdue}\}$：订单状态

### 1.3 无人机状态模型

每架无人机 $u_i$ 的状态定义为：

$$
u_i = (\mathbf{p}_i, \mathbf{v}_i, E_i^{\text{remain}}, Q_i^{\text{max}}, q_i^{\text{current}}, \text{task\_list}_i, \text{status}_i)
$$

其中：
- $\mathbf{p}_i$：当前位置
- $\mathbf{v}_i$：当前速度
- $E_i^{\text{remain}}$：剩余电量
- $Q_i^{\text{max}}$：最大载重量
- $q_i^{\text{current}}$：当前载重
- $\text{task\_list}_i$：已分配的订单队列
- $\text{status}_i \in \{\text{idle}, \text{flying}, \text{picking}, \text{delivering}, \text{charging}\}$：无人机状态

### 1.4 分配矩阵约束

分配矩阵 $\mathbf{A}$ 需满足以下约束：

**约束1：订单唯一性** -- 每个订单最多分配给一架无人机：

$$
\sum_{i=1}^{N} A_{ij} \leq 1, \quad \forall j \in \{1, 2, \ldots, M\}
$$

**约束2：容量约束** -- 无人机当前载重不超过最大载重：

$$
\sum_{j=1}^{M} A_{ij} \cdot w_j \leq Q_i^{\text{max}}, \quad \forall i \in \{1, 2, \ldots, N\}
$$

**约束3：电量约束** -- 无人机剩余电量需满足配送能耗需求：

$$
E_i^{\text{remain}} \geq E_i^{\text{required}}(\text{task\_list}_i), \quad \forall i \in \{1, 2, \ldots, N\}
$$

其中 $E_i^{\text{required}}$ 为完成当前任务列表所需的预估能耗。

**约束4：时间窗口约束** -- 配送需在截止时间前完成：

$$
t_i^{\text{arrival}}(o_j) \leq t_j^{\text{deadline}}, \quad \forall (i,j) \text{ s.t. } A_{ij} = 1
$$

### 1.5 代价矩阵构建

定义代价矩阵 $\mathbf{C} \in \mathbb{R}^{N \times M}$，其中 $C_{ij}$ 表示无人机 $u_i$ 执行订单 $o_j$ 的综合代价：

$$
C_{ij} = \alpha \cdot D_{ij} + \beta \cdot T_{ij} + \gamma \cdot E_{ij} + \delta \cdot P_{ij}
$$

各分量定义如下：

**距离代价** $D_{ij}$：

$$
D_{ij} = \|\mathbf{p}_i - \mathbf{s}_j\| + \|\mathbf{s}_j - \mathbf{d}_j\|
$$

表示无人机从当前位置飞往取货点再到配送点的总距离。

**时间代价** $T_{ij}$：

$$
T_{ij} = \frac{D_{ij}}{v_{\text{avg}}} + t_{\text{hover}}
$$

其中 $v_{\text{avg}}$ 为平均飞行速度，$t_{\text{hover}}$ 为取货/配送悬停时间。

**能耗代价** $E_{ij}$：

$$
E_{ij} = P_{\text{flight}} \cdot \frac{D_{ij}}{v_{\text{avg}}} + P_{\text{hover}} \cdot t_{\text{hover}}
$$

**紧急度代价** $P_{ij}$：

$$
P_{ij} = \max\left(0, \frac{T_{ij}}{t_j^{\text{deadline}} - t_{\text{current}}}\right)
$$

当 $P_{ij} > 1$ 时表示无法在截止时间前完成配送。

**权重参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| $\alpha$ | 0.3 | 距离代价权重 |
| $\beta$ | 0.3 | 时间代价权重 |
| $\gamma$ | 0.2 | 能耗代价权重 |
| $\delta$ | 0.2 | 紧急度代价权重 |

### 1.6 优化目标

**单目标优化** -- 最小化总配送代价：

$$
\min_{\mathbf{A}} \sum_{i=1}^{N} \sum_{j=1}^{M} A_{ij} \cdot C_{ij}
$$

**多目标优化** -- 综合考虑多个优化目标：

$$
\min_{\mathbf{A}} \left( \sum_{i,j} A_{ij} C_{ij}, \quad \max_i \sum_j A_{ij} - \min_i \sum_j A_{ij}, \quad \sum_j \mathbb{1}[t_j^{\text{finish}} > t_j^{\text{deadline}}] \right)
$$

三个目标分别为：总代价最小、负载均衡、延迟订单数最少。

## 二、静态分配算法

### 2.1 贪心算法

#### 2.1.1 算法思想

贪心算法采用"最近优先"策略，每次为当前空闲的无人机分配距离最近的未分配订单。算法简单高效，适合实时性要求高的场景。

#### 2.1.2 算法流程

```
算法1：贪心任务分配算法
输入：订单集合 O，无人机集合 U，代价矩阵 C
输出：分配矩阵 A

1. 初始化 A = 0^{N×M}，未分配订单集合 P = O
2. WHILE P ≠ ∅ DO
3.     FOR each 空闲无人机 u_i DO
4.         IF P = ∅ THEN BREAK
5.         计算 u_i 到所有未分配订单的代价：c_j = C_{ij}, ∀o_j ∈ P
6.         选择代价最小的订单：o* = argmin_{o_j ∈ P} c_j
7.         检查约束条件：
8.           - 容量约束：q_i + w_{o*} ≤ Q_i^{max}
9.           - 电量约束：E_i^{remain} ≥ E_i^{required}(o*)
10.          - 时间约束：t_i^{arrival}(o*) ≤ t_{o*}^{deadline}
11.        IF 所有约束满足 THEN
12.            A_{i,o*} = 1
13.            更新 u_i 状态：q_i += w_{o*}
14.            更新 u_i 任务队列：task_list_i.append(o*)
15.            P = P \ {o*}
16.        ELSE
17.            尝试下一个代价次小的订单
18.        END IF
19.    END FOR
20.    IF 本轮无订单被分配 THEN
21.        等待无人机状态更新
22.    END IF
23. END WHILE
24. RETURN A
```

#### 2.1.3 时间复杂度分析

- 每次分配需要遍历所有未分配订单：$O(M)$
- 每架无人机最多分配 $M/N$ 个订单
- 总时间复杂度：$O(N \cdot M \cdot M/N) = O(M^2)$

#### 2.1.4 优缺点

| 优点 | 缺点 |
|------|------|
| 实现简单，计算速度快 | 无法保证全局最优 |
| 适合实时动态场景 | 可能导致负载不均衡 |
| 易于理解和调试 | 对紧急订单处理不够灵活 |

### 2.2 匈牙利算法

#### 2.2.1 算法思想

匈牙利算法（Hungarian Algorithm）是一种求解二分图最大匹配的经典算法，可在 $O(n^3)$ 时间内找到最优分配方案。当订单数与无人机数相等时，可直接应用；当不相等时，需进行虚拟化处理。

#### 2.2.2 问题转换

当 $M \neq N$ 时，需将代价矩阵扩展为方阵：

**情况1：$M < N$（订单少于无人机）**

添加 $N - M$ 个虚拟订单，虚拟订单的代价为0：

$$
\mathbf{C}' = [\mathbf{C} | \mathbf{0}_{N \times (N-M)}] \in \mathbb{R}^{N \times N}
$$

**情况2：$M > N$（无人机少于订单）**

添加 $M - N$ 架虚拟无人机，虚拟无人机的代价为无穷大（确保不被选中）：

$$
\mathbf{C}' = \begin{bmatrix} \mathbf{C} \\ \infty \cdot \mathbf{1}_{(M-N) \times M} \end{bmatrix} \in \mathbb{R}^{M \times M}
$$

#### 2.2.3 算法流程

```
算法2：匈牙利任务分配算法
输入：代价矩阵 C ∈ R^{N×M}
输出：最优分配矩阵 A

1. 预处理：将 C 扩展为方阵 C' ∈ R^{max(N,M)×max(N,M)}
2. 行规约：每行减去该行最小值
3. 列规约：每列减去该列最小值
4. 寻找独立零元素：
5.   a. 标记包含未被覆盖零元素的行
6.   b. 标记这些零元素所在的列
7.   c. 标记这些列中标记元素所在的行
8.   d. 重复直到无法继续标记
9.   e. 画线覆盖所有未标记行和已标记列
10. WHILE 覆盖线数 < max(N,M) DO
11.     找出未被覆盖的最小元素 θ
12.     未覆盖元素减去 θ
13.     行列交叉元素加上 θ
14.     重新寻找独立零元素
15. END WHILE
16. 根据独立零元素位置构建分配矩阵 A
17. 去除虚拟订单/无人机对应的分配
18. RETURN A
```

#### 2.2.4 Python实现

```python
import numpy as np
from scipy.optimize import linear_sum_assignment

def hungarian_task_allocation(cost_matrix, drone_states, order_list):
    """
    匈牙利算法任务分配

    参数:
        cost_matrix: numpy数组, 形状 (N, M), 代价矩阵
        drone_states: list, 无人机状态列表
        order_list: list, 订单列表

    返回:
        allocation: dict, {drone_id: [order_ids]} 分配结果
    """
    N, M = cost_matrix.shape

    # 处理非方阵情况
    if N < M:
        # 无人机少于订单, 添加虚拟无人机 (代价设为较大值)
        padding = np.full((M - N, M), 1e6)
        extended_cost = np.vstack([cost_matrix, padding])
    elif N > M:
        # 无人机多于订单, 添加虚拟订单 (代价为0, 表示不执行任务)
        padding = np.zeros((N, N - M))
        extended_cost = np.hstack([cost_matrix, padding])
    else:
        extended_cost = cost_matrix.copy()

    # 应用匈牙利算法
    row_ind, col_ind = linear_sum_assignment(extended_cost)

    # 构建分配结果
    allocation = {}
    for i, j in zip(row_ind, col_ind):
        if i < N and j < M:  # 排除虚拟订单/无人机
            # 检查约束条件
            order = order_list[j]
            drone = drone_states[i]

            if check_constraints(drone, order):
                if i not in allocation:
                    allocation[i] = []
                allocation[i].append(j)

    return allocation

def check_constraints(drone, order):
    """检查分配约束条件"""
    # 容量约束
    if drone['current_load'] + order['weight'] > drone['max_load']:
        return False

    # 电量约束 (简化估算)
    distance = compute_distance(drone['position'], order['pickup_pos'])
    distance += compute_distance(order['pickup_pos'], order['delivery_pos'])
    energy_required = distance * 0.5  # 简化的能耗估算
    if drone['remaining_energy'] < energy_required:
        return False

    # 时间约束
    estimated_time = distance / drone['avg_speed']
    if estimated_time > (order['deadline'] - order['current_time']):
        return False

    return True

def compute_distance(pos1, pos2):
    """计算三维欧氏距离"""
    return np.sqrt(sum((a - b) ** 2 for a, b in zip(pos1, pos2)))
```

#### 2.2.5 时间复杂度分析

- 匈牙利算法核心：$O(n^3)$，其中 $n = \max(N, M)$
- 约束检查：$O(N \cdot M)$
- 总时间复杂度：$O(\max(N, M)^3)$

#### 2.2.6 优缺点

| 优点 | 缺点 |
|------|------|
| 保证全局最优解 | 计算复杂度较高 |
| 理论基础扎实 | 不适合大规模实时场景 |
| 可处理不等数量匹配 | 需要预计算完整代价矩阵 |

### 2.3 两种算法对比

| 维度 | 贪心算法 | 匈牙利算法 |
|------|---------|-----------|
| 时间复杂度 | $O(M^2)$ | $O(\max(N,M)^3)$ |
| 空间复杂度 | $O(N \cdot M)$ | $O(N \cdot M)$ |
| 最优性 | 局部最优 | 全局最优 |
| 实时性 | 高 | 中 |
| 适用场景 | 动态实时分配 | 静态批量分配 |
| 负载均衡 | 较差 | 较好 |

## 三、动态调整策略

### 3.1 实时状态感知

#### 3.1.1 状态监测指标

系统实时监测以下状态指标：

| 指标 | 符号 | 更新频率 | 说明 |
|------|------|---------|------|
| 无人机位置 | $\mathbf{p}_i(t)$ | 10 Hz | GPS/定位系统实时更新 |
| 无人机电量 | $E_i(t)$ | 1 Hz | 电池管理系统上报 |
| 订单状态 | $\text{status}_j(t)$ | 事件触发 | 状态变化时更新 |
| 环境信息 | $\text{env}(t)$ | 0.5 Hz | 气象、禁飞区等 |
| 交通拥堵 | $\text{congestion}(t)$ | 0.1 Hz | 空域拥堵指数 |

#### 3.1.2 触发条件

动态调整在以下条件触发：

```
触发条件定义：
1. 新订单到达: new_order_event == True
2. 电量预警: E_i(t) < E_threshold (E_threshold = 20%)
3. 订单超时风险: estimated_arrival > deadline
4. 环境变化: no_fly_zone_updated OR weather_changed
5. 无人机故障: uav_status == FAULT
6. 定期重优化: time_since_last_optimization > T_reopt (T_reopt = 60s)
```

### 3.2 优先级机制

#### 3.2.1 优先级计算

订单优先级由基础优先级和动态优先级两部分组成：

$$
\text{priority}_{\text{total}}(o_j, t) = \text{priority}_{\text{base}}(o_j) + \text{priority}_{\text{dynamic}}(o_j, t)
$$

**基础优先级** $\text{priority}_{\text{base}}$：

根据订单类型设定：

| 订单类型 | 基础优先级 | 说明 |
|---------|-----------|------|
| 医疗急救 | 5 | 血液、药品等紧急物资 |
| 生鲜食品 | 4 | 有时效性要求 |
| 普通快递 | 3 | 标准配送服务 |
| 文件资料 | 2 | 非紧急文件 |
| 其他 | 1 | 无特殊要求 |

**动态优先级** $\text{priority}_{\text{dynamic}}$：

根据时间和状态动态调整：

$$
\text{priority}_{\text{dynamic}}(o_j, t) = \lambda_1 \cdot \text{urgency}(o_j, t) + \lambda_2 \cdot \text{wait}(o_j, t)
$$

其中：

**紧急度函数** $\text{urgency}$：

$$
\text{urgency}(o_j, t) = \begin{cases}
0 & \text{if } \frac{t_j^{\text{deadline}} - t}{t_j^{\text{deadline}} - t_j^{\text{create}}} > 0.5 \\
2 & \text{if } 0.2 < \frac{t_j^{\text{deadline}} - t}{t_j^{\text{deadline}} - t_j^{\text{create}}} \leq 0.5 \\
5 & \text{if } \frac{t_j^{\text{deadline}} - t}{t_j^{\text{deadline}} - t_j^{\text{create}}} \leq 0.2
\end{cases}
$$

**等待时间函数** $\text{wait}$：

$$
\text{wait}(o_j, t) = \min\left(3, \left\lfloor \frac{t - t_j^{\text{create}}}{300} \right\rfloor\right)
$$

每等待5分钟，优先级增加1，最多增加3。

**权重参数**：$\lambda_1 = 0.6$，$\lambda_2 = 0.4$

#### 3.2.2 优先级队列管理

```python
import heapq
from dataclasses import dataclass, field
from typing import List, Tuple

@dataclass(order=True)
class PriorityOrder:
    """优先级订单类"""
    priority: float
    order_id: str = field(compare=False)
    created_time: float = field(compare=False)
    deadline: float = field(compare=False)
    pickup_pos: Tuple[float, float, float] = field(compare=False)
    delivery_pos: Tuple[float, float, float] = field(compare=False)
    weight: float = field(compare=False)

class PriorityQueue:
    """优先级订单队列"""

    def __init__(self):
        self._queue: List[PriorityOrder] = []
        self._index = 0  # 用于相同优先级时的排序

    def push(self, order: PriorityOrder):
        """添加订单到队列"""
        # 负优先级是因为heapq是最小堆
        heapq.heappush(self._queue, order)

    def pop(self) -> PriorityOrder:
        """取出最高优先级订单"""
        if self._queue:
            return heapq.heappop(self._queue)
        return None

    def update_priorities(self, current_time: float):
        """更新所有订单的动态优先级"""
        for order in self._queue:
            order.priority = self._compute_priority(order, current_time)
        heapq.heapify(self._queue)

    def _compute_priority(self, order: PriorityOrder, current_time: float) -> float:
        """计算订单综合优先级"""
        # 紧急度
        time_ratio = (order.deadline - current_time) / (order.deadline - order.created_time)
        if time_ratio <= 0.2:
            urgency = 5
        elif time_ratio <= 0.5:
            urgency = 2
        else:
            urgency = 0

        # 等待时间
        wait_time = min(3, int((current_time - order.created_time) / 300))

        return -(order.priority + 0.6 * urgency + 0.4 * wait_time)  # 负值用于最小堆

    def is_empty(self) -> bool:
        return len(self._queue) == 0

    def size(self) -> int:
        return len(self._queue)
```

### 3.3 负载均衡策略

#### 3.3.1 负载均衡指标

定义无人机 $u_i$ 的负载指标：

$$
L_i(t) = \frac{n_i(t)}{\bar{n}(t)} + \frac{E_i^{\text{consumed}}(t)}{\bar{E}^{\text{consumed}}(t)}
$$

其中：
- $n_i(t)$：无人机 $u_i$ 已完成和待完成的订单数
- $\bar{n}(t)$：所有无人机的平均订单数
- $E_i^{\text{consumed}}(t)$：无人机 $u_i$ 已消耗的电量
- $\bar{E}^{\text{consumed}}(t)$：所有无人机的平均消耗电量

**负载均衡度**：

$$
\text{Balance}(t) = 1 - \frac{\text{std}(\{L_1(t), L_2(t), \ldots, L_N(t)\})}{\text{mean}(\{L_1(t), L_2(t), \ldots, L_N(t)\})}
$$

$\text{Balance}(t) \in [0, 1]$，值越大表示负载越均衡。

#### 3.3.2 负载均衡分配策略

在分配新订单时，引入负载均衡因子：

$$
C_{ij}^{\text{balanced}} = C_{ij} + \lambda_{\text{balance}} \cdot L_i(t)
$$

其中 $\lambda_{\text{balance}}$ 为负载均衡权重（默认值：0.3）。

### 3.4 动态重分配算法

```
算法3：动态任务重分配算法
输入：当前分配 A, 无人机状态 {u_i}, 订单状态 {o_j}, 触发事件 event
输出：更新后的分配 A'

1. 事件处理：
2. CASE event.type OF
3.   NEW_ORDER:
4.     将新订单加入优先级队列
5.     计算新订单与所有空闲无人机的代价
6.     IF 存在可行分配 THEN
7.       选择综合代价最小的无人机进行分配
8.     ELSE
9.       将订单加入等待队列
10.    END IF
11.
12.  BATTERY_LOW:
13.    标记低电量无人机为不可用
14.    获取该无人机的待执行订单列表
15.    FOR each 待执行订单 DO
16.      IF 订单尚未取货 THEN
17.        将订单退回待分配队列
18.      ELSE IF 订单已取货 THEN
19.        优先完成当前配送（不重新分配）
20.      END IF
21.    END FOR
22.    指引无人机前往最近充电站
23.
24.  ORDER_TIMEOUT_RISK:
25.    获取超时风险订单列表
26.    FOR each 超时风险订单 o_j DO
27.      当前执行无人机 u_i = get_assigned_drone(o_j)
28.      计算剩余配送时间 t_remaining
29.      IF t_remaining > (deadline - current_time) THEN
30.        寻找更近的可用无人机 u_k
31.        IF u_k 存在 AND 转移代价 < 超时代价 THEN
32.          执行订单转移：A_{ij} = 0, A_{kj} = 1
33.        END IF
34.      END IF
35.    END FOR
36.
37.  UAV_FAULT:
38.    标记故障无人机为不可用
39.    获取该无人机所有任务
40.    执行全局重分配（调用匈牙利算法）
41.
42.  PERIODIC_REOPT:
43.    计算当前系统负载均衡度
44.    IF Balance(t) < 0.6 THEN
45.      执行局部重分配（仅调整空闲无人机的任务）
46.    END IF
47.    更新所有订单的动态优先级
48.    处理等待队列中的订单
49.
50. END CASE
51. RETURN 更新后的分配 A'
```

## 四、端到端优化：任务分配与路径规划联合优化

### 4.1 联合优化框架

传统的任务分配与路径规划是分离的：先分配订单，再规划路径。这种分离方式可能导致次优解。本项目提出将任务分配融入强化学习框架，实现端到端优化。

#### 4.1.1 联合状态空间

将任务分配信息融入RL状态空间：

$$
\mathbf{s}_i^{\text{joint}} = (\underbrace{\mathbf{p}_i, \mathbf{v}_i}_{\text{运动状态}}, \underbrace{E_i, q_i}_{\text{资源状态}}, \underbrace{\mathbf{g}_i, \mathbf{o}_{\text{pending}}}_{\text{任务状态}}, \underbrace{\mathbf{p}_{\text{other}}, \mathbf{g}_{\text{other}}}_{\text{协同信息}})
$$

各分量说明：
- $\mathbf{p}_i, \mathbf{v}_i$：当前运动状态
- $E_i, q_i$：剩余电量和当前载重
- $\mathbf{g}_i$：当前目标（取货点或配送点）
- $\mathbf{o}_{\text{pending}}$：待分配订单的特征向量（归一化位置、紧急度等）
- $\mathbf{p}_{\text{other}}, \mathbf{g}_{\text{other}}$：其他无人机的位置和目标

#### 4.1.2 联合动作空间

扩展动作空间，包含路径规划动作和任务选择动作：

$$
\mathbf{a}_i = (\underbrace{a_x, a_y, a_z}_{\text{加速度}}, \underbrace{o_{\text{select}}}_{\text{订单选择}})
$$

其中 $o_{\text{select}} \in \{0, 1, \ldots, K\}$ 表示选择的待分配订单编号（0表示不选择新订单）。

#### 4.1.3 联合奖励函数

在原有8项奖励分量基础上，增加任务分配相关奖励：

$$
r_{\text{total}} = r_{\text{path}} + r_{\text{task}}
$$

**路径规划奖励** $r_{\text{path}}$：

$$
r_{\text{path}} = r_{\text{goal}} + r_{\text{collision}} + r_{\text{proximity}} + r_{\text{energy}} + r_{\text{time}} + r_{\text{smooth}}
$$

**任务分配奖励** $r_{\text{task}}$：

$$
r_{\text{task}} = r_{\text{delivery}} + r_{\text{delay}} + r_{\text{balance}}
$$

各分量定义：

**配送完成奖励** $r_{\text{delivery}}$：

$$
r_{\text{delivery}} = \begin{cases}
+50 & \text{if 完成一个订单配送} \\
0 & \text{otherwise}
\end{cases}
$$

**延迟惩罚** $r_{\text{delay}}$：

$$
r_{\text{delay}} = \begin{cases}
-20 & \text{if 配送超时} \\
0 & \text{otherwise}
\end{cases}
$$

**负载均衡奖励** $r_{\text{balance}}$：

$$
r_{\text{balance}} = \begin{cases}
+10 & \text{if Balance}(t) > 0.8 \\
0 & \text{if } 0.6 \leq \text{Balance}(t) \leq 0.8 \\
-5 & \text{if Balance}(t) < 0.6
\end{cases}
$$

### 4.2 PPO训练中的任务分配

#### 4.2.1 集中式训练

在训练阶段，使用全局信息进行任务分配决策：

```python
class JointTaskPathPPO:
    """任务分配与路径规划联合优化的PPO智能体"""

    def __init__(self, config):
        self.num_drones = config.num_drones
        self.max_orders = config.max_orders
        self.state_dim = config.joint_state_dim
        self.action_dim = config.joint_action_dim

        # Actor网络：输出路径动作和订单选择概率
        self.actor = JointActorNetwork(
            state_dim=self.state_dim,
            action_dim=self.action_dim,
            max_orders=self.max_orders
        )

        # Critic网络：评估全局状态价值
        self.critic = GlobalCriticNetwork(
            global_state_dim=config.global_state_dim
        )

    def select_action(self, local_state, available_orders):
        """
        选择动作：路径规划 + 订单选择

        参数:
            local_state: 局部观测状态
            available_orders: 可用订单列表

        返回:
            path_action: 加速度动作 (a_x, a_y, a_z)
            selected_order: 选择的订单索引
        """
        # 前向传播
        path_mean, path_std, order_logits = self.actor(local_state)

        # 采样路径动作
        path_dist = Normal(path_mean, path_std)
        path_action = path_dist.sample()
        path_action = torch.clamp(path_action, -1, 1)

        # 采样订单选择
        if len(available_orders) > 0:
            order_probs = F.softmax(order_logits[:len(available_orders)+1], dim=0)
            order_dist = Categorical(order_probs)
            selected_order = order_dist.sample()
        else:
            selected_order = torch.tensor(0)  # 不选择新订单

        return path_action, selected_order

    def compute_reward(self, global_state, actions, next_global_state):
        """计算联合奖励"""
        reward = 0.0

        # 路径规划奖励
        reward += self._path_reward(global_state, actions, next_global_state)

        # 任务分配奖励
        reward += self._task_reward(global_state, actions, next_global_state)

        return reward

    def _task_reward(self, state, actions, next_state):
        """计算任务分配相关奖励"""
        reward = 0.0

        # 配送完成奖励
        completed_orders = next_state['completed'] - state['completed']
        reward += completed_orders * 50

        # 延迟惩罚
        overdue_orders = next_state['overdue'] - state['overdue']
        reward += overdue_orders * (-20)

        # 负载均衡奖励
        balance = self._compute_balance(next_state['drone_loads'])
        if balance > 0.8:
            reward += 10
        elif balance < 0.6:
            reward -= 5

        return reward
```

#### 4.2.2 分散式执行

在执行阶段，每架无人机独立决策：

```python
class DistributedTaskExecutor:
    """分布式任务执行器"""

    def __init__(self, drone_id, policy_network):
        self.drone_id = drone_id
        self.policy = policy_network
        self.task_queue = []
        self.current_target = None

    def step(self, local_observation, comm_messages):
        """
        执行一步决策

        参数:
            local_observation: 本机观测
            comm_messages: 来自其他无人机的通信消息

        返回:
            action: (path_action, task_decision)
        """
        # 更新本地信息
        self._update_local_info(local_observation, comm_messages)

        # 路径规划动作
        path_action = self.policy.compute_path_action(local_observation)

        # 任务决策（仅在空闲时考虑新任务）
        task_decision = None
        if self.is_idle() and len(self.pending_orders) > 0:
            task_decision = self.policy.select_order(
                local_observation,
                self.pending_orders
            )

        return path_action, task_decision

    def is_idle(self):
        """判断是否空闲"""
        return self.current_target is None and len(self.task_queue) == 0
```

### 5.2 算法选择策略

```python
class AdaptiveAllocator:
    """自适应任务分配器"""

    def __init__(self, config):
        self.greedy_allocator = GreedyAllocator()
        self.hungarian_allocator = HungarianAllocator()
        self.rl_allocator = RLAllocator(config)

    def allocate(self, orders, drones, context):
        """
        根据场景选择分配算法

        参数:
            orders: 待分配订单列表
            drones: 无人机状态列表
            context: 场景上下文信息

        返回:
            allocation: 分配结果
        """
        num_orders = len(orders)
        num_drones = len(drones)
        urgency = self._compute_urgency(orders)

        # 策略选择
        if num_orders <= 3 or urgency > 0.8:
            # 订单少或紧急度高：使用贪心算法（实时性优先）
            return self.greedy_allocator.allocate(orders, drones)
        elif num_orders <= 20 and context.is_static:
            # 订单适中且场景静态：使用匈牙利算法（最优性优先）
            return self.hungarian_allocator.allocate(orders, drones)
        else:
            # 复杂场景：使用强化学习（自适应性优先）
            return self.rl_allocator.allocate(orders, drones, context)

    def _compute_urgency(self, orders):
        """计算整体紧急度"""
        if not orders:
            return 0
        urgency_scores = []
        for order in orders:
            time_ratio = (order.deadline - order.current_time) / \
                         (order.deadline - order.created_time)
            urgency_scores.append(1 - time_ratio)
        return sum(urgency_scores) / len(urgency_scores)
```

本文档设计了无人机物流配送项目的多订单动态任务分配算法，包含以下核心内容：

   - 实时状态感知与事件触发机制

4. **端到端优化**：将任务分配融入PPO强化学习框架，实现任务分配与路径规划的联合优化。

5. **自适应算法选择**：根据场景特点（订单数量、紧急度、场景复杂度）自动选择最合适的分配算法。

该算法设计兼顾了实时性、最优性和自适应性，能够有效支持多无人机协同物流配送系统的运行。

FUNCTION HungarianAllocate(cost_matrix):
    n = max(rows(cost_matrix), cols(cost_matrix))
    C' = extend_to_square(cost_matrix, n)

    // 行规约
    FOR i = 1 to n:
        C'[i,:] -= min(C'[i,:])

    // 列规约
    FOR j = 1 to n:
        C'[:,j] -= min(C'[:,j])

    // 寻找最优分配
    WHILE cover_lines < n:
        find_independent_zeros(C')
        IF cover_lines < n:
            theta = min_uncovered(C')
            adjust_matrix(C', theta)

    RETURN extract_allocation(C')
