## 一、问题建模

### 1.1 输入定义

**无人机集合** $\mathcal{U} = \{u_1, u_2, \ldots, u_N\}$，每架无人机 $u_i$ 的状态定义为：

$$
u_i = (\mathbf{p}_i, \mathbf{v}_i, E_i^{\text{remain}}, Q_i^{\text{max}}, q_i^{\text{current}}, \text{task\_list}_i, \text{status}_i)
$$

| 符号 | 类型 | 说明 |
|------|------|------|
| $\mathbf{p}_i = (x_i, y_i, z_i)$ | 向量 | 当前三维位置 |
| $\mathbf{v}_i = (v_x, v_y, v_z)$ | 向量 | 当前速度 |
| $E_i^{\text{remain}}$ | 标量 | 剩余电量 (Wh) |
| $Q_i^{\text{max}}$ | 标量 | 最大载重量 (kg) |
| $q_i^{\text{current}}$ | 标量 | 当前载重 (kg) |
| $\text{task\_list}_i$ | 列表 | 已分配的订单队列 |
| $\text{status}_i$ | 枚举 | idle / flying / picking / delivering / charging / fault |

无人机可用条件：

$$
\text{is\_available}(u_i) \iff \text{status}_i \in \{\text{idle}, \text{flying}\}
$$

**订单集合** $\mathcal{O} = \{o_1, o_2, \ldots, o_M\}$，每个订单 $o_j$ 定义为七元组：

$$
o_j = (\mathbf{s}_j, \mathbf{d}_j, w_j, t_j^{\text{create}}, t_j^{\text{deadline}}, \text{priority}_j, \text{status}_j)
$$

| 符号 | 类型 | 说明 |
|------|------|------|
| $\mathbf{s}_j = (x_j^s, y_j^s, z_j^s)$ | 向量 | 取货位置（仓库/商家） |
| $\mathbf{d}_j = (x_j^d, y_j^d, z_j^d)$ | 向量 | 配送目标位置（客户） |
| $w_j$ | 标量 | 货物重量 (kg) |
| $t_j^{\text{create}}$ | 标量 | 订单创建时间 |
| $t_j^{\text{deadline}}$ | 标量 | 配送截止时间 |
| $\text{priority}_j \in \{1,2,3,4,5\}$ | 整数 | 基础优先级（5为最高） |
| $\text{status}_j$ | 枚举 | pending / assigned / picking / delivering / completed / overdue |

### 1.2 输出定义

分配矩阵 $\mathbf{A} \in \{0, 1\}^{N \times M}$，其中：

$$
A_{ij} = 1 \iff \text{订单 } o_j \text{ 分配给无人机 } u_i
$$

等价字典表示：$\text{allocation}: \{u_i \to [o_{j_1}, o_{j_2}, \ldots]\}$

### 1.3 约束条件

**约束1 -- 订单唯一性**：每个订单最多分配给一架无人机

$$
\sum_{i=1}^{N} A_{ij} \leq 1, \quad \forall j \in \{1, 2, \ldots, M\}
$$

**约束2 -- 载重约束**：无人机当前载重不超过最大载重

$$
\sum_{j=1}^{M} A_{ij} \cdot w_j \leq Q_i^{\text{max}}, \quad \forall i \in \{1, 2, \ldots, N\}
$$

**约束3 -- 电量约束**：剩余电量满足配送能耗需求（含安全余量）

$$
E_i^{\text{remain}} \geq (1 + \alpha_{\text{safe}}) \cdot E_i^{\text{required}}(\text{task\_list}_i), \quad \forall i
$$

其中 $\alpha_{\text{safe}} = 0.2$ 为电量安全余量。能耗估算采用项目能耗模型：

$$
E_i^{\text{required}} = \int_0^{T_{\text{total}}} P_{\text{flight}}(\tau) \, d\tau = \int_0^{T_{\text{total}}} \frac{k_1 \|\mathbf{v}_h\|^3 + k_2 m g v_z}{\eta_{\text{motor}}} \, d\tau + k_3 m g \cdot t_{\text{hover}}
$$

简化估算：

$$
E_{ij} \approx D_{ij} \cdot e_{\text{unit}}
$$

其中 $D_{ij}$ 为总飞行距离，$e_{\text{unit}}$ 为单位距离能耗（典型值 0.5 Wh/m）。

**约束4 -- 时间窗口约束**：配送需在截止时间前完成

$$
t_i^{\text{arrival}}(o_j) \leq t_j^{\text{deadline}} \cdot (1 - \beta_{\text{safe}}), \quad \forall (i,j) \text{ s.t. } A_{ij} = 1
$$

其中 $\beta_{\text{safe}} = 0.1$ 为时间安全余量，到达时间估算：

$$
t_i^{\text{arrival}}(o_j) = t_{\text{current}} + \frac{\|\mathbf{p}_i - \mathbf{s}_j\| + \|\mathbf{s}_j - \mathbf{d}_j\|}{v_{\text{avg}}} + t_{\text{hover}}
$$

### 1.4 优化目标

**单目标优化** -- 最小化总配送代价：

$$
\min_{\mathbf{A}} \sum_{i=1}^{N} \sum_{j=1}^{M} A_{ij} \cdot C_{ij}
$$

**多目标优化** -- 综合考虑效率、均衡性和时效性：

$$
\min_{\mathbf{A}} \left( \underbrace{\sum_{i,j} A_{ij} C_{ij}}_{\text{总代价}}, \quad \underbrace{\max_i \sum_j A_{ij} - \min_i \sum_j A_{ij}}_{\text{负载差异}}, \quad \underbrace{\sum_j \mathbb{1}[t_j^{\text{finish}} > t_j^{\text{deadline}}]}_{\text{延迟订单数}} \right)
$$

### 1.5 代价矩阵构建

定义代价矩阵 $\mathbf{C} \in \mathbb{R}^{N \times M}$，其中 $C_{ij}$ 表示无人机 $u_i$ 执行订单 $o_j$ 的综合代价：

$$
C_{ij} = \alpha \cdot D_{ij} + \beta \cdot T_{ij} + \gamma \cdot E_{ij} + \delta \cdot P_{ij} + \lambda_{\text{balance}} \cdot L_i(t)
$$

各分量定义如下。

**距离代价** $D_{ij}$：

$$
D_{ij} = \|\mathbf{p}_i - \mathbf{s}_j\|_2 + \|\mathbf{s}_j - \mathbf{d}_j\|_2
$$

表示无人机从当前位置飞往取货点再到配送点的总距离。

**时间代价** $T_{ij}$：

$$
T_{ij} = \frac{D_{ij}}{v_{\text{avg}}} + t_{\text{hover}}
$$

其中 $v_{\text{avg}} = 15$ m/s 为平均飞行速度，$t_{\text{hover}} = 30$ s 为取货/配送悬停时间。

**能耗代价** $E_{ij}$（基于项目能耗模型）：

$$
E_{ij} = P_{\text{flight}} \cdot \frac{D_{ij}}{v_{\text{avg}}} + P_{\text{hover}} \cdot t_{\text{hover}}
$$

其中 $P_{\text{flight}} = \frac{k_1 v_{\text{avg}}^3}{\eta_{\text{motor}}}$，$P_{\text{hover}} = k_3 \cdot m \cdot g$。

**紧急度代价** $P_{ij}$：

$$
P_{ij} = \max\left(0, \frac{T_{ij}}{t_j^{\text{deadline}} - t_{\text{current}}}\right)
$$

当 $P_{ij} > 1$ 时表示无法在截止时间前完成配送。

**负载均衡因子** $L_i(t)$：

$$
L_i(t) = \frac{|\text{task\_list}_i|}{n_{\max}} + \frac{E_i^{\text{max}} - E_i^{\text{remain}}}{E_i^{\text{max}}}
$$

**权重参数**：

| 参数 | 符号 | 默认值 | 取值范围 | 说明 |
|------|------|--------|---------|------|
| 距离代价权重 | $\alpha$ | 0.3 | [0, 1] | 距离在总代价中的权重 |
| 时间代价权重 | $\beta$ | 0.3 | [0, 1] | 时间在总代价中的权重 |
| 能耗代价权重 | $\gamma$ | 0.2 | [0, 1] | 能耗在总代价中的权重 |
| 紧急度代价权重 | $\delta$ | 0.2 | [0, 1] | 紧急度在总代价中的权重 |
| 负载均衡权重 | $\lambda_{\text{balance}}$ | 0.3 | [0, 1] | 负载均衡的权重 |

## 二、静态分配算法

### 2.1 贪心算法

#### 2.1.1 算法思想

贪心算法采用"最近优先"策略，每次为空闲的无人机分配代价最小的未分配订单。算法简单高效，适合实时性要求高的动态场景。

#### 2.1.2 算法流程

```
算法1：贪心任务分配算法
输入：订单集合 O，无人机集合 U，代价矩阵 C
输出：分配矩阵 A

1.  初始化 A = 0^{N×M}，未分配订单集合 P = O
2.  WHILE P ≠ ∅ DO
3.      assigned_in_round = False
4.      FOR each 空闲无人机 u_i DO
5.          IF P = ∅ THEN BREAK
6.          计算 u_i 到所有未分配订单的代价：c_j = C_{ij}, ∀o_j ∈ P
7.          按代价升序排列 P 中的订单
8.          FOR each o_j in sorted_P DO
9.              检查约束条件：
10.               容量：q_i + w_j ≤ Q_i^{max}
11.               电量：E_i^{remain} ≥ (1+α_safe) * E_required(u_i, o_j)
12.               时间：t_arrival(u_i, o_j) ≤ t_j^{deadline} * (1-β_safe)
13.             IF 所有约束满足 THEN
14.                 A_{i,j} = 1
15.                 更新 u_i 状态：q_i += w_j，task_list_i.append(o_j)
16.                 P = P \ {o_j}
17.                 assigned_in_round = True
18.                 BREAK
19.             END IF
20.         END FOR
21.     END FOR
22.     IF NOT assigned_in_round THEN BREAK  // 无法继续分配
23. END WHILE
24. RETURN A
```

#### 2.1.3 复杂度分析

- 每次分配需遍历所有未分配订单：$O(M)$
- 每架无人机最多分配 $M/N$ 个订单
- 总时间复杂度：$O(M^2)$
- 空间复杂度：$O(N \cdot M)$

#### 2.1.4 适用场景与局限

| 优点 | 缺点 |
|------|------|
| 实现简单，计算速度快（<1ms） | 无法保证全局最优 |
| 适合实时动态场景 | 可能导致负载不均衡 |
| 易于理解和调试 | 先分配的无人机占据优势资源 |

### 2.2 匈牙利算法

#### 2.2.1 算法思想

匈牙利算法（Hungarian Algorithm）求解二分图最优匹配，在 $O(n^3)$ 时间内找到全局最优分配方案。当订单数与无人机数不相等时，需进行虚拟化扩展。

#### 2.2.2 问题转换

当 $M \neq N$ 时，将代价矩阵扩展为方阵：

**情况1：$M > N$（订单多于无人机）** -- 添加虚拟无人机（高代价）：

$$
\mathbf{C}' = \begin{bmatrix} \mathbf{C} \\ C_{\text{penalty}} \cdot \mathbf{1}_{(M-N) \times M} \end{bmatrix} \in \mathbb{R}^{M \times M}
$$

其中 $C_{\text{penalty}} = 10^6$，确保虚拟无人机不会被选中执行真实订单。

**情况2：$M < N$（无人机多于订单）** -- 添加虚拟订单（零代价）：

$$
\mathbf{C}' = [\mathbf{C} \mid \mathbf{0}_{N \times (N-M)}] \in \mathbb{R}^{N \times N}
$$

虚拟订单代价为0，表示不执行任务。

#### 2.2.3 算法流程

```
算法2：匈牙利任务分配算法
输入：订单集合 O，无人机集合 U，代价矩阵 C ∈ R^{N×M}
输出：最优分配矩阵 A

1.  预处理：将 C 扩展为方阵 C' ∈ R^{n×n}，n = max(N, M)
2.  行规约：每行减去该行最小值
3.  列规约：每列减去该列最小值
4.  寻找独立零元素：
5.    a. 标记包含未被覆盖零元素的行
6.    b. 标记这些零元素所在的列
7.    c. 标记这些列中标记元素所在的行
8.    d. 重复直到无法继续标记
9.    e. 画线覆盖所有未标记行和已标记列
10. WHILE 覆盖线数 < n DO
11.     找出未被覆盖的最小元素 θ
12.     未覆盖元素减去 θ
13.     行列交叉元素加上 θ
14.     重新寻找独立零元素
15. END WHILE
16. 根据独立零元素位置构建分配矩阵 A
17. 去除虚拟订单/无人机对应的分配
18. 对每个分配对 (u_i, o_j) 检查约束：
19.     容量约束、电量约束、时间窗口约束
20.     不满足约束的分配标记为无效
21. RETURN A
```

#### 2.2.4 复杂度分析

- 匈牙利算法核心：$O(n^3)$，其中 $n = \max(N, M)$
- 约束检查：$O(N \cdot M)$
- 总时间复杂度：$O(\max(N, M)^3)$
- 空间复杂度：$O(N \cdot M)$

#### 2.2.5 适用场景与局限

| 优点 | 缺点 |
|------|------|
| 保证全局最优解（单目标） | 计算复杂度较高（10~100ms） |
| 理论基础扎实 | 不适合大规模实时场景 |
| 可处理不等数量匹配 | 需要预计算完整代价矩阵 |

### 2.3 强化学习分配

#### 2.3.1 算法思想

将任务分配建模为马尔可夫决策过程（MDP），使用PPO算法学习最优分配策略。该方法能够处理多目标优化，适应动态环境，并与路径规划实现端到端联合优化。

#### 2.3.2 MDP建模

**状态空间** $\mathcal{S}$：

$$
\mathbf{s}_t = \left( \underbrace{\mathbf{p}_i, \mathbf{v}_i}_{\text{运动状态}}, \underbrace{E_i, q_i}_{\text{资源状态}}, \underbrace{\mathbf{g}_i, \mathbf{o}_{\text{pending}}}_{\text{任务状态}}, \underbrace{\mathbf{p}_{\text{other}}, \mathbf{g}_{\text{other}}}_{\text{协同信息}} \right)
$$

其中 $\mathbf{o}_{\text{pending}}$ 为待分配订单的特征向量（归一化位置、紧急度、重量等）。

**动作空间** $\mathcal{A}$：

$$
\mathbf{a}_t = (\underbrace{a_x, a_y, a_z}_{\text{加速度}}, \underbrace{o_{\text{select}}}_{\text{订单选择}})
$$

其中 $o_{\text{select}} \in \{0, 1, \ldots, K\}$，0表示不选择新订单。

**奖励函数**：

$$
r_{\text{total}} = r_{\text{path}} + r_{\text{task}}
$$

路径规划奖励 $r_{\text{path}}$ 包含目标到达、碰撞惩罚、间距惩罚、能耗惩罚、时间惩罚、平滑惩罚等（详见奖励函数设计文档）。

任务分配奖励 $r_{\text{task}}$：

$$
r_{\text{task}} = r_{\text{delivery}} + r_{\text{delay}} + r_{\text{balance}}
$$

| 分量 | 公式 | 说明 |
|------|------|------|
| $r_{\text{delivery}}$ | $+50 \times \Delta n_{\text{completed}}$ | 完成配送奖励 |
| $r_{\text{delay}}$ | $-20 \times \Delta n_{\text{overdue}}$ | 超时惩罚 |
| $r_{\text{balance}}$ | $+10$ if Balance > 0.8; $-5$ if Balance < 0.6 | 负载均衡奖惩 |

#### 2.3.3 PPO训练框架

采用CTDE（Centralized Training with Decentralized Execution）架构：

**训练阶段**（集中式）：
- 使用全局状态信息训练集中式Critic
- 各智能体共享经验池，加速学习
- 使用全局奖励信号更新策略
- 参数共享的Actor网络：$\theta_1 = \theta_2 = \cdots = \theta_N = \theta$

**执行阶段**（分散式）：
- 各智能体仅使用局部观测做决策
- 无需通信，独立执行

**网络结构**：

| 组件 | 结构 | 激活函数 | 输出维度 |
|------|------|---------|---------|
| Actor | Linear(D,256) -> Linear(256,128) -> Linear(128,64) | ReLU | 3(均值) + 3(对数标准差) + K+1(订单选择logits) |
| Critic | Linear(D,256) -> Linear(256,128) -> Linear(128,64) | Tanh | 1 (状态价值) |

**核心超参数**：

| 参数 | 符号 | 值 |
|------|------|-----|
| 学习率 | $\alpha$ | $3 \times 10^{-4}$ |
| 折扣因子 | $\gamma$ | 0.99 |
| GAE参数 | $\lambda$ | 0.95 |
| 裁剪参数 | $\epsilon$ | 0.2 |
| 价值损失系数 | $c_1$ | 0.5 |
| 熵系数 | $c_2$ | 0.01 |
| 最大梯度范数 | $c$ | 0.5 |
| 批次大小 | $B$ | 256 |
| 更新轮次 | $K$ | 4 |

#### 2.3.4 复杂度分析

- 训练阶段：取决于episode长度和更新轮次
- 推理阶段：单次前向传播约 1~5ms
- 适用场景：复杂动态环境、多目标优化、需要与路径规划联合优化的场景

### 2.4 三种算法对比

| 维度 | 贪心算法 | 匈牙利算法 | 强化学习分配 |
|------|---------|-----------|-------------|
| 时间复杂度 | $O(M^2)$ | $O(\max(N,M)^3)$ | 1~5ms（推理） |
| 空间复杂度 | $O(N \cdot M)$ | $O(N \cdot M)$ | 网络参数量 |
| 最优性 | 局部最优 | 全局最优（单目标） | 近似全局最优（多目标） |
| 实时性 | 高（<1ms） | 中（10~100ms） | 高（推理） |
| 适用场景 | 动态实时分配 | 静态批量分配 | 复杂动态场景 |
| 负载均衡 | 较差 | 较好 | 好 |
| 多目标处理 | 不支持 | 不支持 | 原生支持 |

## 三、动态调整策略

### 3.1 实时状态感知

#### 3.1.1 状态监测指标

| 指标 | 符号 | 更新频率 | 说明 |
|------|------|---------|------|
| 无人机位置 | $\mathbf{p}_i(t)$ | 10 Hz | GPS/定位系统实时更新 |
| 无人机电量 | $E_i(t)$ | 1 Hz | 电池管理系统上报 |
| 订单状态 | $\text{status}_j(t)$ | 事件触发 | 状态变化时更新 |
| 环境信息 | $\text{env}(t)$ | 0.5 Hz | 气象、禁飞区等 |

#### 3.1.2 触发事件类型

```python
class TriggerEvent(Enum):
    NEW_ORDER = "new_order"              # 新订单到达
    BATTERY_LOW = "battery_low"          # 电量预警（SOC < 20%）
    TIMEOUT_RISK = "timeout_risk"        # 超时风险（est_arrival > deadline）
    UAV_FAULT = "uav_fault"              # 无人机故障
    PERIODIC_REOPT = "periodic_reopt"    # 定期重优化（T_reopt = 60s）
```

### 3.2 优先级机制

#### 3.2.1 优先级计算

订单综合优先级由基础优先级和动态优先级两部分组成：

$$
\text{priority}_{\text{total}}(o_j, t) = \text{priority}_{\text{base}}(o_j) + \lambda_1 \cdot \text{urgency}(o_j, t) + \lambda_2 \cdot \text{wait}(o_j, t)
$$

**基础优先级** $\text{priority}_{\text{base}}$：

| 订单类型 | 基础优先级 | 说明 |
|---------|-----------|------|
| 医疗急救 | 5 | 血液、药品等紧急物资 |
| 生鲜食品 | 4 | 有时效性要求 |
| 普通快递 | 3 | 标准配送服务 |
| 文件资料 | 2 | 非紧急文件 |
| 其他 | 1 | 无特殊要求 |

**紧急度函数** $\text{urgency}(o_j, t)$：

$$
\text{urgency}(o_j, t) = \begin{cases}
5 & \text{if } \frac{t_j^{\text{deadline}} - t}{t_j^{\text{deadline}} - t_j^{\text{create}}} \leq 0.2 \\
2 & \text{if } 0.2 < \frac{t_j^{\text{deadline}} - t}{t_j^{\text{deadline}} - t_j^{\text{create}}} \leq 0.5 \\
0 & \text{otherwise}
\end{cases}
$$

**等待时间函数** $\text{wait}(o_j, t)$：

$$
\text{wait}(o_j, t) = \min\left(3, \left\lfloor \frac{t - t_j^{\text{create}}}{300} \right\rfloor\right)
$$

每等待5分钟，优先级增加1，最多增加3。

**权重参数**：$\lambda_1 = 0.6$，$\lambda_2 = 0.4$

#### 3.2.2 优先级队列管理

使用最大堆（heapq取负值）维护订单优先级队列，支持动态更新：

- 新订单到达时计算优先级并入队
- 定期（每次重优化时）更新所有订单的动态优先级
- 分配时始终取出优先级最高的订单

### 3.3 负载均衡策略

#### 3.3.1 负载均衡指标

定义无人机 $u_i$ 的负载指标：

$$
L_i(t) = \frac{|\text{task\_list}_i(t)|}{n_{\max}} + \frac{E_i^{\text{max}} - E_i^{\text{remain}}(t)}{E_i^{\text{max}}}
$$

**负载均衡度**：

$$
\text{Balance}(t) = 1 - \frac{\text{std}(\{L_1(t), \ldots, L_N(t)\})}{\text{mean}(\{L_1(t), \ldots, L_N(t)\})}
$$

$\text{Balance}(t) \in [0, 1]$，值越大表示负载越均衡。

#### 3.3.2 负载均衡代价调整

在分配新订单时，将负载因子加入代价矩阵：

$$
C_{ij}^{\text{balanced}} = C_{ij} + \lambda_{\text{balance}} \cdot L_i(t)
$$

负载较高的无人机在代价矩阵中的代价值增大，从而降低其被选中的概率。

### 3.4 动态重分配算法

```
算法3：动态任务重分配
输入：当前分配 A，无人机状态 {u_i}，订单状态 {o_j}，触发事件 event
输出：更新后的分配 A'

CASE event.type OF

  NEW_ORDER:
    将新订单加入优先级队列
    获取空闲无人机集合
    IF 存在空闲无人机 THEN
      使用贪心算法快速分配（实时性优先）
    ELSE
      将订单加入等待队列
    END IF

  BATTERY_LOW:
    标记低电量无人机为不可用（status = CHARGING）
    获取该无人机的待执行订单列表
    FOR each 待执行订单 o_j DO
      IF o_j.status == ASSIGNED THEN  // 尚未取货
        将 o_j 退回待分配队列（status = PENDING）
      ELSE IF o_j.status in {PICKING, DELIVERING} THEN
        优先完成当前配送（不重新分配）
      END IF
    END FOR
    使用贪心算法将退回的订单分配给其他可用无人机
    指引故障无人机前往最近充电站

  TIMEOUT_RISK:
    获取有超时风险的订单列表
    FOR each 超时风险订单 o_j DO
      找到当前执行无人机 u_i = get_assigned(o_j)
      计算剩余配送时间 t_remaining
      IF t_remaining > (deadline - current_time) THEN
        寻找更近的可用无人机 u_k
        IF u_k 存在 AND 转移后可按时完成 THEN
          执行订单转移：从 u_i 移除 o_j，分配给 u_k
        END IF
      END IF
    END FOR

  UAV_FAULT:
    标记故障无人机为不可用（status = FAULT）
    获取该无人机所有未完成任务
    将所有未取货订单退回待分配队列
    使用匈牙利算法对退回订单进行全局最优重分配

  PERIODIC_REOPT:
    计算当前系统负载均衡度 Balance(t)
    IF Balance(t) < 0.6 THEN
      获取待分配订单和空闲无人机
      使用带负载均衡的贪心算法分配
    END IF
    更新所有订单的动态优先级
    处理等待队列中的订单

END CASE
RETURN 更新后的分配 A'
```

### 3.5 订单转移机制

当需要将订单从一架无人机转移到另一架时：

```
算法4：订单转移
输入：源无人机 u_src，目标无人机 u_dst，待转移订单 o_j
输出：转移是否成功

IF o_j.status == PENDING THEN
  // 订单尚未分配/取货，直接重新分配
  从 u_src 任务队列移除 o_j
  将 o_j 加入 u_dst 任务队列
  更新分配矩阵 A
  RETURN True

ELSE IF o_j.status == ASSIGNED THEN
  // 订单已分配但未取货
  IF u_dst 距离取货点更近 AND u_dst 能按时完成 THEN
    从 u_src 任务队列移除 o_j
    将 o_j 加入 u_dst 任务队列
    更新分配矩阵 A
    RETURN True
  ELSE
    RETURN False
  END IF

ELSE IF o_j.status == PICKING THEN
  // 订单正在取货，一般不转移
  IF u_src.status == FAULT THEN  // 仅故障时转移
    计算货物交接点
    规划交接路径
    执行货物交接
    u_dst 继续完成配送
    RETURN True
  ELSE
    RETURN False
  END IF

ELSE IF o_j.status == DELIVERING THEN
  // 订单正在配送，一般不转移
  // 仅在无人机故障等紧急情况下转移
  RETURN False

END IF
```

## 四、端到端联合优化

### 4.1 联合优化框架

传统方法将任务分配与路径规划分离（先分配再规划），可能导致次优解。本项目将任务分配融入强化学习框架，实现端到端联合优化。

#### 4.1.1 联合状态空间

$$
\mathbf{s}_i^{\text{joint}} = (\underbrace{\mathbf{p}_i, \mathbf{v}_i}_{\text{运动状态}}, \underbrace{E_i, q_i}_{\text{资源状态}}, \underbrace{\mathbf{g}_i, \mathbf{o}_{\text{pending}}}_{\text{任务状态}}, \underbrace{\mathbf{p}_{\text{other}}, \mathbf{g}_{\text{other}}}_{\text{协同信息}})
$$

状态维度：$D = 10 + (M+1)$，其中10为连续状态维度，$(M+1)$ 为配送进度独热编码。

#### 4.1.2 联合动作空间

$$
\mathbf{a}_i = (\underbrace{a_x, a_y, a_z}_{\text{加速度}}, \underbrace{o_{\text{select}}}_{\text{订单选择}})
$$

#### 4.1.3 联合奖励函数

$$
r_{\text{total}} = r_{\text{path}} + r_{\text{task}}
$$

路径规划奖励：$r_{\text{path}} = R_{\text{goal}} + P_{\text{collision}} + P_{\text{proximity}} + P_{\text{formation}} + P_{\text{energy}} + P_{\text{time}} + P_{\text{smooth}}$

任务分配奖励：$r_{\text{task}} = r_{\text{delivery}} + r_{\text{delay}} + r_{\text{balance}}$

### 4.2 联合优化的优势

| 维度 | 分离优化 | 联合优化 |
|------|---------|---------|
| 全局最优性 | 局部最优 | 接近全局最优 |
| 适应性 | 需要重新优化 | 实时自适应 |
| 计算效率 | 分步计算 | 端到端计算 |
| 协同能力 | 有限 | 强 |
| 实现复杂度 | 低 | 高 |

            return self.hungarian_allocator.allocate(orders, drones, current_time)

$$
\text{urgency} = \frac{1}{M} \sum_{j=1}^{M} \left( 1 - \frac{t_j^{\text{deadline}} - t_{\text{current}}}{t_j^{\text{deadline}} - t_j^{\text{create}}} \right)
$$

紧急度越接近1，表示整体订单越紧急。

### 7.2 代价矩阵构建器

```python
class CostMatrixBuilder:
    """代价矩阵构建器"""

    def __init__(self,
                 alpha: float = 0.3,      # 距离权重
                 beta: float = 0.3,       # 时间权重
                 gamma: float = 0.2,      # 能耗权重
                 delta: float = 0.2,      # 紧急度权重
                 lambda_balance: float = 0.3):  # 负载均衡权重
        self.alpha = alpha
        self.beta = beta
        self.gamma = gamma
        self.delta = delta
        self.lambda_balance = lambda_balance

    def build(self,
              drones: List[Drone],
              orders: List[Order],
              current_time: float) -> np.ndarray:
        """构建代价矩阵 C ∈ R^{N×M}"""
        N = len(drones)
        M = len(orders)
        cost_matrix = np.zeros((N, M))

        for i, drone in enumerate(drones):
            for j, order in enumerate(orders):
                cost_matrix[i, j] = self._compute_cost(drone, order, current_time)

        return cost_matrix

    def _compute_cost(self,
                      drone: Drone,
                      order: Order,
                      current_time: float) -> float:
        """计算单个无人机-订单对的综合代价"""
        # 距离代价
        dist_to_pickup = drone.position.distance_to(order.pickup_pos)
        dist_pickup_to_delivery = order.pickup_pos.distance_to(order.delivery_pos)
        total_distance = dist_to_pickup + dist_pickup_to_delivery

        # 时间代价
        estimated_time = total_distance / drone.avg_speed

        # 能耗代价
        energy_consumption = total_distance * 0.5  # Wh/m

        # 紧急度代价
        time_remaining = order.deadline - current_time
        if time_remaining > 0:
            urgency = estimated_time / time_remaining
        else:
            urgency = 10.0

        # 负载均衡代价
        load_factor = len(drone.task_list) / 10.0

        # 综合代价
        cost = (self.alpha * total_distance +
                self.beta * estimated_time +
                self.gamma * energy_consumption +
                self.delta * urgency +
                self.lambda_balance * load_factor)

        return cost
```

### 7.3 约束检查器

```python
class ConstraintChecker:
    """约束条件检查器"""

    def __init__(self,
                 energy_safety_margin: float = 0.2,
                 time_safety_margin: float = 0.1):
        self.energy_safety_margin = energy_safety_margin
        self.time_safety_margin = time_safety_margin

    def check_all(self,
                  drone: Drone,
                  order: Order,
                  current_time: float) -> Tuple[bool, str]:
        """检查所有约束条件"""
        # 容量约束
        if drone.current_load + order.weight > drone.max_load:
            return False, "容量超限"

        # 电量约束
        energy_required = self._estimate_energy(drone, order)
        if drone.remaining_energy < energy_required * (1 + self.energy_safety_margin):
            return False, "电量不足"

        # 时间约束
        estimated_arrival = self._estimate_arrival_time(drone, order, current_time)
        if estimated_arrival > order.deadline * (1 - self.time_safety_margin):
            return False, "无法按时送达"

        return True, "满足所有约束"

    def _estimate_energy(self, drone: Drone, order: Order) -> float:
        total_distance = (drone.position.distance_to(order.pickup_pos) +
                          order.pickup_pos.distance_to(order.delivery_pos))
        return total_distance * 0.5

    def _estimate_arrival_time(self,
                                drone: Drone,
                                order: Order,
                                current_time: float) -> float:
        total_distance = (drone.position.distance_to(order.pickup_pos) +
                          order.pickup_pos.distance_to(order.delivery_pos))
        flight_time = total_distance / drone.avg_speed
        hover_time = 30.0
        return current_time + flight_time + hover_time
```

### 7.4 贪心分配器

```python
class GreedyAllocator:
    """
    贪心任务分配算法
    时间复杂度: O(M^2)
    适用场景: 实时动态分配
    """

    def __init__(self):
        self.cost_builder = CostMatrixBuilder()
        self.constraint_checker = ConstraintChecker()

    def allocate(self,
                 orders: List[Order],
                 drones: List[Drone],
                 current_time: float) -> AllocationResult:
        allocation = {drone.drone_id: [] for drone in drones}
        unassigned = list(orders)
        total_cost = 0.0

        cost_matrix = self.cost_builder.build(drones, orders, current_time)

        while unassigned:
            assigned_in_round = False

            for i, drone in enumerate(drones):
                if not drone.is_available or not unassigned:
                    continue

                best_order = None
                best_cost = float('inf')
                best_idx = -1

                for j, order in enumerate(unassigned):
                    original_idx = orders.index(order)
                    cost = cost_matrix[i, original_idx]
                    is_valid, _ = self.constraint_checker.check_all(
                        drone, order, current_time
                    )

                    if is_valid and cost < best_cost:
                        best_cost = cost
                        best_order = order
                        best_idx = j

                if best_order is not None:
                    allocation[drone.drone_id].append(best_order.order_id)
                    drone.task_list.append(best_order.order_id)
                    drone.current_load += best_order.weight
                    best_order.status = OrderStatus.ASSIGNED
                    unassigned.pop(best_idx)
                    total_cost += best_cost
                    assigned_in_round = True

            if not assigned_in_round:
                break

        return AllocationResult(
            allocation=allocation,
            total_cost=total_cost,
            algorithm="greedy",
            timestamp=current_time
        )
```

### 7.5 匈牙利分配器

```python
class HungarianAllocator:
    """
    匈牙利任务分配算法
    时间复杂度: O(max(N,M)^3)
    适用场景: 静态批量分配
    """

    def __init__(self):
        self.cost_builder = CostMatrixBuilder()
        self.constraint_checker = ConstraintChecker()

    def allocate(self,
                 orders: List[Order],
                 drones: List[Drone],
                 current_time: float) -> AllocationResult:
        N = len(drones)
        M = len(orders)

        if N == 0 or M == 0:
            return AllocationResult({}, 0.0, "hungarian", current_time)

        # 构建代价矩阵
        cost_matrix = self.cost_builder.build(drones, orders, current_time)

        # 处理非方阵情况
        extended_cost, _ = self._extend_to_square(cost_matrix, N, M)

        # 应用匈牙利算法
        row_ind, col_ind = linear_sum_assignment(extended_cost)

        # 构建分配结果
        allocation = {drone.drone_id: [] for drone in drones}
        total_cost = 0.0

        for i, j in zip(row_ind, col_ind):
            if i >= N or j >= M:
                continue

            drone = drones[i]
            order = orders[j]

            is_valid, _ = self.constraint_checker.check_all(drone, order, current_time)

            if is_valid:
                allocation[drone.drone_id].append(order.order_id)
                drone.task_list.append(order.order_id)
                drone.current_load += order.weight
                order.status = OrderStatus.ASSIGNED
                total_cost += cost_matrix[i, j]

        return AllocationResult(
            allocation=allocation,
            total_cost=total_cost,
            algorithm="hungarian",
            timestamp=current_time
        )

    def _extend_to_square(self, cost_matrix, N, M):
        """将代价矩阵扩展为方阵"""
        n = max(N, M)
        extended = np.zeros((n, n))

        if N < M:
            extended[:N, :M] = cost_matrix
            extended[N:, :] = 1e6  # 虚拟无人机高代价
        elif N > M:
            extended[:N, :M] = cost_matrix
            # 虚拟订单代价为0
        else:
            extended = cost_matrix.copy()

        padding_info = {"original_N": N, "original_M": M, "extended_size": n}
        return extended, padding_info
```

### 7.6 优先级管理器

```python
class PriorityManager:
    """优先级管理器"""

    def __init__(self,
                 lambda_urgency: float = 0.6,
                 lambda_wait: float = 0.4):
        self.lambda_urgency = lambda_urgency
        self.lambda_wait = lambda_wait
        self._queue = []

    def add_order(self, order: Order, current_time: float):
        score = self._compute_priority(order, current_time)
        # 负值用于最大堆
        heapq.heappush(self._queue, (-score, id(order), order))

    def pop_highest(self) -> Optional[Order]:
        if self._queue:
            _, _, order = heapq.heappop(self._queue)
            return order
        return None

    def update_all_priorities(self, current_time: float):
        updated = []
        while self._queue:
            _, _, order = heapq.heappop(self._queue)
            new_score = self._compute_priority(order, current_time)
            updated.append((-new_score, id(order), order))
        self._queue = updated
        heapq.heapify(self._queue)

    def _compute_priority(self, order: Order, current_time: float) -> float:
        base_priority = order.priority

        # 紧急度
        time_ratio = (order.deadline - current_time) / max(
            order.deadline - order.created_time, 1
        )
        if time_ratio <= 0.2:
            urgency = 5
        elif time_ratio <= 0.5:
            urgency = 2
        else:
            urgency = 0

        # 等待时间
        wait_time = min(3, int((current_time - order.created_time) / 300))

        total = base_priority + self.lambda_urgency * urgency + self.lambda_wait * wait_time
        return total

    @property
    def is_empty(self) -> bool:
        return len(self._queue) == 0
```

### 7.7 负载均衡器

```python
class LoadBalancer:
    """负载均衡管理器"""

    def compute_load_metrics(self, drones: List[Drone]) -> Dict[str, float]:
        metrics = {}
        for drone in drones:
            task_factor = len(drone.task_list) / 10.0
            energy_factor = (drone.max_energy - drone.remaining_energy) / drone.max_energy
            metrics[drone.drone_id] = task_factor + energy_factor
        return metrics

    def compute_balance_score(self, drones: List[Drone]) -> float:
        """计算负载均衡度 Balance ∈ [0, 1]"""
        metrics = self.compute_load_metrics(drones)
        values = list(metrics.values())

        if not values or all(v == 0 for v in values):
            return 1.0

        mean_val = np.mean(values)
        std_val = np.std(values)

        if mean_val == 0:
            return 1.0

        balance = 1.0 - (std_val / mean_val)
        return max(0.0, min(1.0, balance))
```

### 7.8 动态重分配器

```python
class DynamicReallocator:
    """动态任务重分配器"""

    def __init__(self):
        self.greedy_allocator = GreedyAllocator()
        self.hungarian_allocator = HungarianAllocator()
        self.priority_manager = PriorityManager()
        self.load_balancer = LoadBalancer()
        self.constraint_checker = ConstraintChecker()

    def handle_event(self,
                     event: TriggerEvent,
                     drones: List[Drone],
                     orders: List[Order],
                     current_allocation: Dict[str, List[str]],
                     current_time: float,
                     **kwargs) -> AllocationResult:
        """处理触发事件并执行重分配"""
        if event == TriggerEvent.NEW_ORDER:
            return self._handle_new_order(
                kwargs.get('new_order'),
                drones, orders, current_allocation, current_time
            )
        elif event == TriggerEvent.BATTERY_LOW:
            return self._handle_battery_low(
                kwargs.get('drone_id'),
                drones, orders, current_allocation, current_time
            )
        elif event == TriggerEvent.TIMEOUT_RISK:
            return self._handle_timeout_risk(
                drones, orders, current_allocation, current_time
            )
        elif event == TriggerEvent.UAV_FAULT:
            return self._handle_uav_fault(
                kwargs.get('drone_id'),
                drones, orders, current_allocation, current_time
            )
        elif event == TriggerEvent.PERIODIC_REOPT:
            return self._handle_periodic_reopt(
                drones, orders, current_allocation, current_time
            )
        else:
            return AllocationResult(current_allocation, 0.0, "none", current_time)

    def _handle_new_order(self, new_order, drones, orders,
                          current_allocation, current_time):
        pending_orders = [o for o in orders if o.status == OrderStatus.PENDING]
        pending_orders.append(new_order)
        idle_drones = [d for d in drones if d.is_available]

        if not idle_drones or not pending_orders:
            return AllocationResult(current_allocation, 0.0, "no_change", current_time)

        result = self.greedy_allocator.allocate(pending_orders, idle_drones, current_time)

        merged = current_allocation.copy()
        for drone_id, order_ids in result.allocation.items():
            if drone_id in merged:
                merged[drone_id].extend(order_ids)
            else:
                merged[drone_id] = order_ids

        return AllocationResult(merged, result.total_cost, "greedy_new_order", current_time)

    def _handle_battery_low(self, drone_id, drones, orders,
                            current_allocation, current_time):
        low_battery_drone = next((d for d in drones if d.drone_id == drone_id), None)
        if not low_battery_drone:
            return AllocationResult(current_allocation, 0.0, "no_change", current_time)

        low_battery_drone.status = DroneStatus.CHARGING

        pending_order_ids = current_allocation.get(drone_id, [])
        orders_to_reassign = [
            o for o in orders
            if o.order_id in pending_order_ids and o.status == OrderStatus.ASSIGNED
        ]

        for order in orders_to_reassign:
            order.status = OrderStatus.PENDING

        if orders_to_reassign:
            available = [d for d in drones if d.is_available and d.drone_id != drone_id]
            if available:
                result = self.greedy_allocator.allocate(
                    orders_to_reassign, available, current_time
                )
                merged = current_allocation.copy()
                merged[drone_id] = []
                for did, oids in result.allocation.items():
                    if did in merged:
                        merged[did].extend(oids)
                    else:
                        merged[did] = oids
                return AllocationResult(
                    merged, result.total_cost, "greedy_battery_low", current_time
                )

        return AllocationResult(current_allocation, 0.0, "no_reassignment", current_time)

    def _handle_timeout_risk(self, drones, orders, current_allocation, current_time):
        merged = current_allocation.copy()
        # 找出有超时风险的订单并尝试转移给更近的无人机
        for order in orders:
            if order.status not in [OrderStatus.ASSIGNED, OrderStatus.PICKING]:
                continue
            assigned_drone = self._find_assigned_drone(
                order.order_id, drones, current_allocation
            )
            if not assigned_drone:
                continue

            dist = assigned_drone.position.distance_to(order.delivery_pos)
            est_time = dist / assigned_drone.avg_speed + 30
            if est_time <= (order.deadline - current_time):
                continue

            # 寻找更近的可用无人机
            best_drone = None
            best_time = float('inf')
            for drone in drones:
                if not drone.is_available or drone.drone_id == assigned_drone.drone_id:
                    continue
                d = drone.position.distance_to(order.pickup_pos)
                t = d / drone.avg_speed + order.delivery_distance / drone.avg_speed + 30
                if t < best_time and t < (order.deadline - current_time):
                    best_time = t
                    best_drone = drone

            if best_drone:
                if assigned_drone.drone_id in merged:
                    merged[assigned_drone.drone_id] = [
                        oid for oid in merged[assigned_drone.drone_id]
                        if oid != order.order_id
                    ]
                if best_drone.drone_id not in merged:
                    merged[best_drone.drone_id] = []
                merged[best_drone.drone_id].append(order.order_id)

        return AllocationResult(merged, 0.0, "timeout_transfer", current_time)

    def _handle_uav_fault(self, drone_id, drones, orders,
                          current_allocation, current_time):
        fault_drone = next((d for d in drones if d.drone_id == drone_id), None)
        if not fault_drone:
            return AllocationResult(current_allocation, 0.0, "no_change", current_time)

        fault_drone.status = DroneStatus.FAULT

        fault_order_ids = current_allocation.get(drone_id, [])
        fault_orders = [
            o for o in orders
            if o.order_id in fault_order_ids and o.status != OrderStatus.COMPLETED
        ]

        for order in fault_orders:
            order.status = OrderStatus.PENDING

        available = [d for d in drones if d.is_available and d.drone_id != drone_id]
        pending = [o for o in orders if o.status == OrderStatus.PENDING]

        if available and pending:
            result = self.hungarian_allocator.allocate(pending, available, current_time)
            merged = current_allocation.copy()
            merged[drone_id] = []
            for did, oids in result.allocation.items():
                if did in merged:
                    merged[did].extend(oids)
                else:
                    merged[did] = oids
            return AllocationResult(
                merged, result.total_cost, "hungarian_fault_recovery", current_time
            )

        return AllocationResult(current_allocation, 0.0, "partial_recovery", current_time)

    def _handle_periodic_reopt(self, drones, orders, current_allocation, current_time):
        balance_score = self.load_balancer.compute_balance_score(drones)

        if balance_score < 0.6:
            pending = [o for o in orders if o.status == OrderStatus.PENDING]
            idle = [d for d in drones if d.is_available]
            if pending and idle:
                result = self.greedy_allocator.allocate(pending, idle, current_time)
                merged = current_allocation.copy()
                for did, oids in result.allocation.items():
                    if did in merged:
                        merged[did].extend(oids)
                    else:
                        merged[did] = oids
                return AllocationResult(
                    merged, result.total_cost, "periodic_reopt", current_time
                )

        self.priority_manager.update_all_priorities(current_time)
        return AllocationResult(current_allocation, 0.0, "no_reopt_needed", current_time)

    def _find_assigned_drone(self, order_id, drones, allocation):
        for drone_id, order_ids in allocation.items():
            if order_id in order_ids:
                return next((d for d in drones if d.drone_id == drone_id), None)
        return None
```

### 7.9 自适应分配器（主入口）

```python
class AdaptiveAllocator:
    """
    自适应任务分配器
    根据场景特点自动选择最合适的分配算法
    """

    def __init__(self, config: dict = None):
        self.config = config or {}
        self.greedy_allocator = GreedyAllocator()
        self.hungarian_allocator = HungarianAllocator()
        self.dynamic_reallocator = DynamicReallocator()
        self.priority_manager = PriorityManager()
        self.load_balancer = LoadBalancer()

    def allocate(self,
                 orders: List[Order],
                 drones: List[Drone],
                 current_time: float,
                 is_static: bool = True) -> AllocationResult:
        num_orders = len(orders)
        urgency = self._compute_urgency(orders, current_time)

        if num_orders <= 3 or urgency > 0.8:
            return self.greedy_allocator.allocate(orders, drones, current_time)
        elif num_orders <= 20 and is_static:
            return self.hungarian_allocator.allocate(orders, drones, current_time)
        else:
            return self.hungarian_allocator.allocate(orders, drones, current_time)

    def _compute_urgency(self, orders: List[Order], current_time: float) -> float:
        if not orders:
            return 0.0
        scores = []
        for order in orders:
            time_ratio = (order.deadline - current_time) / max(
                order.deadline - order.created_time, 1
            )
            scores.append(1 - time_ratio)
        return sum(scores) / len(scores)
```

## 十、总结

本文档设计了多无人机协同物流配送系统的任务分配算法，核心内容如下：

1. **问题建模**：定义了完整的输入（N架无人机状态 + M个配送订单）、输出（分配矩阵 $\mathbf{A} \in \{0,1\}^{N \times M}$）、约束条件（订单唯一性、载重、电量、时间窗口）和优化目标（最小化总时间、总能耗、负载均衡）。

2. **三种静态分配算法**：
   - 贪心算法：$O(M^2)$，适合实时动态分配
   - 匈牙利算法：$O(\max(N,M)^3)$，保证全局最优
   - 强化学习分配：PPO + CTDE框架，支持多目标联合优化

3. **动态调整策略**：
   - 五种触发事件（新订单、电量预警、超时风险、无人机故障、定期重优化）
   - 多维度优先级计算（基础优先级 + 紧急度 + 等待时间）
   - 负载均衡策略与代价矩阵调整
   - 订单转移机制

4. **端到端联合优化**：将任务分配融入PPO强化学习框架，实现任务分配与路径规划的联合优化。

5. **自适应算法选择**：根据订单数量、紧急度和场景复杂度自动选择最合适的分配算法。

6. **完整Python实现**：包含数据结构、代价矩阵构建、约束检查、贪心分配器、匈牙利分配器、优先级管理器、负载均衡器、动态重分配器、自适应分配器等完整模块。

该算法设计与项目中的能耗模型（`能耗模型设计.md`）、奖励函数设计（`reward_function_design.md`）、PPO算法设计（`PPO算法设计.md`）、状态空间设计（`状态空间设计.md`）等模块保持一致，共同构成完整的多无人机协同物流配送系统。
