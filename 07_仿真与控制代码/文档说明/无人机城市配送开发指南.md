## 1.1 项目简介

### 任务介绍

**目标**：训练一个多无人机协同系统，使其在复杂城市环境中自动规划最优配送路径，完成12个配送点之间的物流配送任务。无人机需要避开所有障碍物（建筑物、河流、高压线、禁飞区等），同时满足载重、高度、能耗等约束。

在创建训练任务和评估任务时，上述元素的配置方式有所不同。具体请查看环境详述-环境配置部分。

### 计分规则

任务得分与配送完成度、飞行效率有关，任务结束时会按下方规则计算任务得分：

**任务得分 = 配送得分 + 效率得分 - 惩罚得分**

- **配送得分**：每完成一个配送点，获得500分。全部完成额外获得1000分。
- **效率得分**：朝目标移动的进度奖励，每步最多+50分。
- **惩罚得分**：碰撞障碍物、进入禁飞区等行为的惩罚。

**注意**：如果无人机电池耗尽或超过最大步数，则任务结束。

## 1.2 环境详述

### 环境配置

在智能体和环境的交互中，首先会调用env.reset方法，该方法接受一个config参数，这个参数通过读取config.py文件的内容来实现定制化的环境配置。因此，用户可以通过修改config.py文件中的内容来调整环境配置。

```python
# config为环境配置
from config import ENV_CONFIG
env = UrbanAirspaceEnv(ENV_CONFIG)
state = env.reset()
```

城市空域环境配置包含的属性如下：

| 数据名 | 数据类型 | 数据描述 |

### 环境数据

在调用env.reset与env.step接口时，会返回环境当前的状态。其中env.reset接口返回state数据，而env.step接口会额外返回reward和done数据。下面将对这些环境状态的各项数据及其含义进行详细的介绍，帮助用户更好的理解每个返回值的作用。

```python
# 重置环境
state = env.reset()

# 执行动作
next_state, reward, done, info = env.step(action)
```

#### 环境返回信息

**env.reset()**

| 数据名 | 数据类型 | 数据描述 |
|--------|----------|----------|
| state | ndarray | 环境状态向量，shape=(num_drones * 14,) |

**env.step(action)**

| 数据名 | 数据类型 | 数据描述 |
|--------|----------|----------|
| state | ndarray | 下一时刻状态向量 |
| reward | float | 当前步的即时奖励 |
| done | bool | 是否任务结束 |
| info | dict | 额外信息（调试用） |

**info字典内容**

| 数据名 | 数据类型 | 数据描述 |
|--------|----------|----------|
| step | int | 当前步数 |
| delivered | int | 已完成配送的无人机数量 |
| total_delivered | int | 总配送完成点数 |
| collisions | int | 碰撞次数 |
| battery_soc | list | 各无人机电池SOC |
| payload | list | 各无人机当前载重 |

#### 状态信息（state）

state是环境实例针对智能体返回的状态信息，包括每架无人机的位置、速度、电池状态、目标信息等。

**单架无人机状态（14维）**

| 维度 | 数据名 | 数据类型 | 数据描述 |
|------|--------|----------|----------|
| 1-3 | position | float | 无人机位置(x, y, z)，归一化到[-1, 1] |
| 4-6 | velocity | float | 无人机速度(vx, vy, vz)，归一化到[-1, 1] |
| 7 | battery_soc | float | 电池SOC(0-1)，0表示耗尽 |
| 8 | payload | float | 当前载重，归一化到[0, 1] |
| 9 | target_distance | float | 到目标点的距离，归一化到[0, 1] |
| 10-12 | target_direction | float | 到目标点的方向向量(x, y, z)，单位向量 |
| 13 | obstacle_distance | float | 到最近障碍物的距离，归一化到[0, 1] |
| 14 | delivery_progress | float | 配送进度(0-1)，已完成/总配送点 |

### 动作空间

智能体输出动作为每架无人机的三维加速度，具体如下：

| 维度 | 数据名 | 取值范围 | 单位 | 说明 |
|------|--------|----------|------|------|
| 1 | ax | [-5.0, 5.0] | m/s² | X方向加速度 |
| 2 | ay | [-5.0, 5.0] | m/s² | Y方向加速度 |
| 3 | az | [-5.0, 5.0] | m/s² | Z方向加速度 |

**动作约束**

- 速度约束：速度不超过15 m/s
- 高度约束：高度在10-150m范围内
- 边界约束：位置不超出空域范围

**动作处理流程**

```
原始动作 → 加速度裁剪 → 速度更新 → 速度约束 → 位置更新 → 边界约束
```

### 奖励函数

奖励函数由多个分量组成，具体如下：

| 分量 | 公式 | 权重 | 说明 |
|------|------|------|------|
| 进度奖励 | +50 × progress | 50 | 朝目标移动的进度 |
| 接近奖励 | +100 × (1 - d/100) | 100 | 100m内渐进奖励 |
| 到达奖励 | +500 | 500 | 到达目标点 |
| 配送完成 | +1000 | 1000 | 全部配送完成 |
| 建筑物碰撞 | -100 | -100 | 碰撞建筑物 |
| 河流碰撞 | -200 | -200 | 碰撞河流 |
| 高压线碰撞 | -150 | -150 | 碰撞高压线 |
| 禁飞区碰撞 | -500 | -500 | 进入禁飞区 |
| 能耗惩罚 | -0.01 × power | 0.01 | 能耗惩罚 |
| 时间惩罚 | -0.1 | 0.1 | 每步时间惩罚 |

**奖励计算公式**

```
总奖励 = 进度奖励 + 接近奖励 + 到达奖励 + 配送完成 + 碰撞惩罚 + 能耗惩罚 + 时间惩罚
```

## 1.3 算法设计

### PPO算法

采用Proximal Policy Optimization (PPO)算法，核心特点：

- **Actor网络**：3层全连接网络 [256, 128, 64]，ReLU激活函数
- **Critic网络**：3层全连接网络 [256, 128, 64]，Tanh激活函数
- **裁剪目标**：限制策略更新幅度，保证训练稳定性
- **GAE优势估计**：平衡偏差与方差

### CTDE框架

采用Centralized Training with Decentralized Execution (CTDE)框架：

- **训练阶段**：集中式Critic，使用全局状态信息
- **执行阶段**：分散式Actor，仅使用局部观测

### 课程学习

采用4阶段课程学习，从简单到复杂逐步训练：

| 阶段 | UAV | 目标 | 障碍物 | 说明 |
|------|-----|------|--------|------|
| 1 | 1 | 1 | 简单 | 基础导航学习 |
| 2 | 1 | 1 | 复杂 | 避障能力学习 |
| 3 | 3 | 1 | 复杂 | 协同策略学习 |
| 4 | 3 | 12 | 全部 | 完整任务训练 |

### B. 常见问题

**Q: 训练不收敛怎么办？**
A: 检查奖励函数设计，确保进度奖励足够强，惩罚不要过大。

**Q: 碰撞检测不准确？**
A: 调整障碍物的radius参数，确保覆盖实际碰撞区域。

**Q: 训练速度太慢？**
A: 减少max_steps，或使用GPU加速。

**Q: 无人机不移动？**
A: 检查奖励函数是否有正向引导，确保进度奖励权重足够大。
